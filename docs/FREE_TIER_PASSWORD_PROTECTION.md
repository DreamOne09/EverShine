# 🔐 免費版密碼洩漏保護實作

## 📋 問題說明

**Supabase 免費版不提供洩漏密碼保護功能**

根據 Supabase 官方文件，洩漏密碼保護（Leaked Password Protection）功能需要：
- ✅ **Pro 方案或以上**才有此功能
- ❌ **免費版（Free Tier）**沒有此功能

這就是為什麼您在 Dashboard 中找不到此設定的原因。

---

## ✅ 解決方案：應用層面實作

我已經在應用層面實作了密碼洩漏檢查功能：

### 已建立的檔案

1. **`src/lib/passwordSecurity.ts`** - 密碼安全檢查工具
   - 使用 HaveIBeenPwned API 檢查密碼
   - 使用 k-anonymity 方法（只傳送雜湊前 5 個字元，保護隱私）
   - 已整合到註冊流程中

2. **`src/pages/Login.tsx`** - 已更新註冊驗證
   - 註冊時自動檢查密碼是否洩漏
   - 如果密碼已洩漏，會顯示錯誤訊息

---

## 🔍 功能說明

### 如何運作

1. **使用者註冊時**：
   - 輸入密碼後，系統會自動檢查
   - 使用 HaveIBeenPwned API（免費、公開的服務）
   - 使用 k-anonymity 方法，**不會傳送完整密碼**

2. **如果密碼已洩漏**：
   - 顯示錯誤訊息：「此密碼已在洩漏資料庫中，請使用更安全的密碼」
   - 阻止註冊，要求使用者更換密碼

3. **如果密碼安全**：
   - 繼續正常註冊流程

### 隱私保護

- ✅ **k-anonymity 方法**：只傳送密碼 SHA-1 雜湊的前 5 個字元
- ✅ **完整密碼不會被傳送**到外部服務
- ✅ 使用 HaveIBeenPwned 的公開 API（免費、可信）

## 🧪 測試方式

### 測試 1：使用洩漏的密碼

1. 前往註冊頁面
2. 嘗試使用已知洩漏的密碼註冊，例如：
   - `password123`
   - `12345678`
   - `qwerty123`
3. 應該會看到錯誤訊息：「此密碼已在洩漏資料庫中」

### 測試 2：使用安全的密碼

1. 使用隨機生成的強密碼
2. 應該可以正常註冊

## ⚠️ 注意事項

1. **API 可用性**：
   - 如果 HaveIBeenPwned API 無法使用，系統會允許密碼通過（不阻擋使用者）
   - 這是為了避免 API 故障時影響使用者體驗

2. **效能**：
   - 每次註冊會多一個 API 請求（約 100-200ms）
   - 對使用者體驗影響很小

3. **未來升級**：
   - 如果升級到 Supabase Pro，可以移除此實作
   - 或保留作為雙重檢查
